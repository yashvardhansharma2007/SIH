# TerraWatch — AI Earth Observation Change & Risk Platform

A working full-stack prototype for SIH PS18: satellite change-detection
(NDVI/NDWI) + a lightweight AI forecasting layer, wrapped in a web
dashboard with a map and trend charts.

## What's actually in here

- **backend/data_gen.py** — generates realistic synthetic NDVI/NDWI
  monthly time series for 4 regions (a deforestation trend, a stable
  forest, a flood-then-recovery water body, and a slow "early warning"
  decline). This stands in for a real Sentinel-2 / Google Earth Engine
  pull so the whole platform runs offline, instantly, with zero API keys
  — important for demo-day reliability.
- **backend/model.py** — the AI layer. Fits a linear trend to the last
  12 months of readings for a region, forecasts N months ahead, and
  classifies the region into a risk tier (Low / Medium / High /
  Recovering) with a plain-language explanation.
- **backend/main.py** — FastAPI serving `/api/regions` (list + current
  risk) and `/api/regions/{id}` (full history + forecast).
- **frontend/index.html** — single-file dashboard: dark "mission
  control" theme, a Leaflet map with risk-colored region markers, and a
  Chart.js trend chart with a dashed AI-forecast segment. No build step.

## Run it

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Then just open `frontend/index.html` in a browser. It calls
`http://localhost:8000` — edit `API_BASE` at the top of the `<script>`
if you deploy the backend somewhere else.

## Getting real satellite data (Google Earth Engine)

`regions.json` currently ships with synthetic-but-realistic NDVI/NDWI
data (generated by `data_gen.py`) so the platform runs instantly with
zero setup. To back it with **real** Sentinel-2 data:

1. Register a free Earth Engine project at
   https://code.earthengine.google.com (pick Noncommercial — no billing
   needed for hackathon-scale use).
2. Easiest path: open a Google Colab notebook (has `earthengine-api`
   preinstalled). Locally instead: `pip install -r requirements-gee.txt`.
3. Authenticate once:
   ```python
   import ee
   ee.Authenticate()
   ee.Initialize(project="YOUR-PROJECT-ID")
   ```
4. Run the real fetch script (takes a few minutes — 16 regions × 24
   monthly Sentinel-2 composites each):
   ```bash
   python gee_fetch.py --project YOUR-PROJECT-ID
   ```
   This overwrites `regions.json` with real, cloud-masked NDVI/NDWI
   values pulled from Sentinel-2 SR Harmonized imagery. `main.py` and
   `model.py` need zero changes — they only depend on the JSON shape,
   not where the numbers came from.
5. **Built-in fallback**: `regions_fallback.json` keeps the synthetic
   dataset as a safety net. If `regions.json` is missing, or a region
   comes back with too many cloud-blocked null months, the backend
   automatically falls back to synthetic data instead of crashing —
   important for demo-day wifi reliability. Check the server console
   for `[warn] falling back to synthetic data: ...` if this triggers.

## Where the "innovation" story lives for judges

Raw before/after change detection is something every PS18 team will
submit. This project's differentiation is the **forecast + risk
tiering layer**: instead of just showing what changed, it projects the
trend forward and gives a plain-language, actionable risk read
("projected 30% drop in 6 months — flag for field verification"),
which is the part worth emphasizing in your pitch.
